# Подключение Codex к Blender

Версия: **2026.09.08.1**, дата: **08.09.2026**. Исполнитель: **Codex / GPT-6 Astra**.

Локальный MCP-сервер для библиотеки котлов PREMIUM. Официальный Python SDK MCP
обслуживает STDIO, отдельный процесс установленного Blender выполняет операции
через штатный `bpy`. Проверено на Blender 3.3.3 и Python 3.13.1 в Windows.

## Поведение

- Каждое MCP-соединение получает собственную фоновую сцену Blender. Уже открытые
  пользовательские окна не меняются. Отдельный Blender завершается при отключении.
- Порты не открываются. Внутренний обмен идёт через приватные каналы родительского
  и дочернего процессов. Нет внешних сервисов, API-ключей или телеметрии моста.
- Импортируется только embedded GLB из явно заданного каталога. STEP/DWG этот
  выпуск не конвертирует. URI, выход из каталога и неподдерживаемые файлы отклоняются.
- Масштаб импорта задаётся явно. У имеющихся старых моделей числовые координаты
  записаны в миллиметрах; `0.001` переводит их в метры. Геометрическую точность
  и точки присоединения необходимо отдельно сверять с CAD-исходниками.
- После импорта, создания, перемещения и открытия копии сохраняется новый `.blend`.
  Все копии, GLB и PNG получают уникальные имена. Исходные файлы не перезаписываются.
- Новая MCP-сессия начинается пустой. Для продолжения вызвать список сохранённых
  сцен и открыть нужную копию. Произвольные `.blend` вне каталога результатов
  недоступны; автоматическое выполнение скриптов отключено.
- При неопределённом результате обмена нет повторной отправки команды. Соединение
  необходимо переоткрыть, затем проверить сохранённые сцены. Ошибка Blender после
  начала изменения явно сообщает о возможном частичном изменении сцены.
- Предпросмотр использует CPU Cycles, автоматически размещённые камеру и свет.
  Это проверочное изображение, а не окончательное рекламное оформление.

## Инструменты MCP

| Команда | Назначение |
|---|---|
| `blender_status` | Подключение, версия Blender, сессия и последняя копия |
| `blender_list_assets` | Доступные GLB |
| `blender_scene_info` | Объекты, иерархия и габариты сцены |
| `blender_object_info` | Положение и габариты объекта |
| `blender_import_glb` | Импорт с явным масштабом |
| `blender_create_primitive` | Куб, цилиндр или сфера |
| `blender_set_transform` | Положение, поворот в радианах и масштаб |
| `blender_save_scene` | Новая копия Blender |
| `blender_list_saved_scenes` | Список сохранённых копий |
| `blender_open_saved_scene` | Открытие управляемой копии в отдельной сцене |
| `blender_export_glb` | Экспорт в GLB |
| `blender_render_preview` | PNG и изображение в ответе MCP |

Исполнение произвольного Python, удаление, загрузка интернет-моделей и управление
AutoCAD не предоставляются этим сервером. Отдельное подключение AutoCAD
версии 2026.09.08.2 проверено после перезапуска; оно описано в
[PR #2](https://github.com/lexcrirovs-prog/3d_komplektacii_na_par/pull/2).

После перезапуска инструменты Blender проверены непосредственно в задаче Codex.
Первичная сборка PR.3000 с горелкой и каталог восьми моделей описаны в
[ASSET_READINESS.md](ASSET_READINESS.md).

## Установка и проверка

Использовать отдельный Python 3.13 venv. `requirements.lock.txt` фиксирует весь
проверенный набор зависимостей; `requirements.txt` фиксирует прямую зависимость.
SDK 1.30.0 — закреплённый выпуск поддерживаемой ветки MCP 1.x.

```powershell
python -m pip install -r tools/blender_bridge/requirements.lock.txt
python -m unittest discover -s tools/blender_bridge/tests -v
python tools/blender_bridge/smoke_test.py --blender '<путь к blender.exe>' --assets '<каталог GLB>' --runtime '<локальный каталог результатов>'
```

`install.py` копирует проверенный код в стабильный каталог `releases/2026.09.08.1`,
создаёт резервную копию полного `config.toml` вне Git и добавляет единственный сервер
`blender` с точным списком из 12 команд. Остальные настройки сравниваются до записи.
Существующее подключение с таким именем автоматически не заменяется.

Параметры установщика: `--install-root`, `--config`, `--blender`, `--python`,
`--assets`; все пути задаются явно. После установки проверить `codex mcp get blender`
и повторить smoke из установленного каталога. Полную конфигурацию и её резервную
копию нельзя прикладывать к GitHub: там могут находиться данные других подключений.

Smoke использует реальный MCP-клиент: `initialize`, `tools/list`, операции с тестовым
кубом, повторное соединение, восстановление копии, импорт настоящего котла, экспорт
GLB и PNG, отрицательные проверки путей/произвольного кода и SHA-256 всех исходников.

Для отключения выполнить `codex mcp remove blender`. Копии моделей, код выпуска,
venv и резервная копия конфигурации сохраняются. Восстанавливать весь старый
`config.toml` поверх более новых настроек без сравнения не следует.

## Основания выбора

- [MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
- [Официальный Python SDK, поддерживаемая ветка 1.x](https://github.com/modelcontextprotocol/python-sdk/tree/v1.x).
- [Работа Astra через Python API Blender](https://learn.chatgpt.com/blog/architectural-visualization-with-astra).

Вместо установки стороннего Blender-плагина с универсальным исполнением кода
используется небольшой собственный мост с явными операциями. Зависимости SDK
устанавливаются из PyPI. Сам мост не использует OpenAI API и не требует отдельного
API-ключа; LLM работает на стороне Codex.
