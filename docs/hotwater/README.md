## Что меняется

В существующем конфигураторе появились два самостоятельных раздела: «Паровые котлы» и «Водогрейные котлы». Для нового раздела используется `?section=hotwater`. Старые параметры паровой сборки сохраняются при переходе между разделами.

Водогрейный каталог содержит 48 самостоятельных общих сборок CLA, E и E Long. Мощность, исполнение, исходное обозначение и габарит берутся из выбранного файла. Большая модель не получается масштабированием меньшей.

Пользователь может вращать модель, переключать ракурсы, открывать фронтовую дверь или две створки, выбирать детали и приближать их. При выборе деталь несколько раз подсвечивается своим исходным цветом. Ручное вращение снимает активное состояние кнопки ракурса. Переходы камеры и дверей плавные; системная настройка уменьшения анимации учитывается.

Пять категорий опций загружаются отдельно: сбросной клапан, переходная плита, дистанционная проставка, коллектор, шкаф автоматики. Опции показываются рядом с котлом в натуральном масштабе. Пользователь может перемещать их и поворачивать на 90°. Ссылка сохраняет выбранный котёл, опции, смещения и поворот. В карточках опций раскрываются назначение, исходный чертёж и ограничения конкретной визуализации.

## Исходники и границы применимости

Подробный отбор описан в [SOURCES.md](SOURCES.md). Состав и контрольные суммы STEP — в [source-selection.json](source-selection.json). Описания опций — в [OPTIONS.md](OPTIONS.md).

Коммерческие названия «тепличный» и «для перегретой воды» не назначаются по имени папки. Найденные документы подтверждают одну цельную дверь у обновлённого E, две симметричные створки у E Long и температурные варианты 115/150 °C в руководстве Long. Соответствие коммерческих категорий конкретным каталогам уточняется у владельца. В интерфейсе сохранены исходные семейства и обозначения вариантов.

CLA на трубе 51 и 57 мм представлены отдельно: документа об отмене 51-мм версии нет. По умолчанию открывается CLA-250 на трубе 57 мм. Переработанный E-3500.01 Long от 09.06.2026 не смешивается с прежним E Long-3500.

Примерка аксессуаров не является подтверждением совместимости креплений. Коллекторы и шкафы восстановлены по чертежам с явно указанными принятыми размерами. Геометрия клапана взята из существующей паровой модели; давление срабатывания, DN и пригодность к водяному контуру не заявляются. Исходные STEP/DXF/PDF не изменялись.

## Почему раздел загружается отдельно

- Начальная оболочка динамически импортирует только выбранный раздел и его CSS. Паровой каталог не входит в граф загрузки водогрейного раздела.
- Каталог содержит адреса файлов; наличие адреса не запускает загрузку. Браузер запрашивает ровно одну выбранную сборку. Остальные 47 моделей не предзагружаются.
- Опции запрашиваются при включении. Устаревшие запросы отменяются; завершившийся старый запрос не может заменить новую модель.
- GLB использует локальный Meshopt-декодер, общие mesh buffers и повторное использование геометрии при рендеринге. Удаления исходных поверхностей нет.
- Рендер работает по событиям: движение, загрузка, подсветка, двери. В неподвижной сцене непрерывная отрисовка прекращается.
- При замене модели освобождаются геометрии, материалы и текстуры. При переходе в другой раздел предыдущий WebGL-контекст уничтожается.
- Имена файлов Vite содержат хеш. Для неизменных GLB/JS/CSS используется длительное кэширование; HTML и версия проверяются заново.

## Воспроизведение моделей

Среда STEP: Python 3.11, cadquery-ocp 7.8.1.1, numpy. Среда опций дополнительно использует Blender 3.3.3 и ezdxf. Для meshopt нужны @gltf-transform 4.2.1 и meshoptimizer 0.23 из существующей среды `S3000_GLTF_RUNTIME`.

```powershell
python tools/hotwater/build_catalog.py docs/hotwater/source-selection.json `
  --source-root '<CAD_ROOT>' `
  --metadata 'OUTPUT\converted-metadata' --up-axis y --workers 4
python tools/hotwater/build_doors.py --metadata 'OUTPUT\converted-metadata' --write
node tools/hotwater/compress_models.mjs src/assets/hotwater OUTPUT\uncompressed OUTPUT\compression.json
node tools/hotwater/verify_catalog.mjs OUTPUT\catalog-verification.json
```

Оси дверей вычисляются до сжатия, по именованным парам шарнирных осей исходной сборки. Повторный запуск `build_doors.py` на сжатом GLB отклоняется: индексы узлов после оптимизации могут измениться. Для повторной генерации следует использовать соответствующий несжатый производный файл и его метаданные.

В клиентском коде дверная группа ищется по `extras.occurrenceLabel`, а не по номеру узла или имени, которое GLTFLoader может изменить.

## Сборка и проверка

```powershell
npm run build
node --experimental-strip-types --test tools/hotwater/configuration.test.mjs
node --test tools/hotwater/section-loading.test.mjs
node --test tools/s3000/visibility.test.mjs tools/s3000/web-budget.test.mjs
node tools/hotwater/check-browser.mjs http://127.0.0.1:5195/ OUTPUT\browser
node tools/hotwater/check-lifecycle.mjs http://127.0.0.1:5195/ OUTPUT\lifecycle
```

Браузерные проверки используют существующий Playwright через переменную `S3000_BROWSER_RUNTIME`. Проверки браузера, структуры CAD, исходников и публикации имеют отдельные результаты. Сводка фактического прогона находится в [VALIDATION.md](VALIDATION.md).

Пакет сборки не должен включать подробные локальные журналы заказов, список заказчиков, исходный CAD или абсолютные служебные пути. Внешние исходники остаются вне репозитория. Папка `output/` исключена из Git.
