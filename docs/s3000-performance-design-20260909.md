# Оптимизация веб-версии S-3000 от 9 сентября 2026

Исполнитель: Codex / GPT-6. Версия веб-поставки: 2026.09.09.1.
Подробная сборка остается 2026.09.08.4. База: `b70031e`, опубликованный код: `023cac30d706fa1a37aafa98f037ed2c96393244`.

## Согласованный объем

Оптимизировать существующий конфигуратор и опубликовать проверенный результат по прежнему адресу. Сохранить внешний вид, приборы, горелку, деаэратор, кабели, обе полные схемы питания, выбор деталей, карточки и параметр `addons` в URL. Подробные Blender/GLB не перезаписывать. Работать только в отдельной копии вложенного репозитория.

## Измерения до реализации

- Chrome 152, Windows, Core i7-12700K, Intel UHD 770 / ANGLE D3D11. Аппаратное ускорение подтверждено строкой WebGL renderer.
- Desktop: 1280×720, DPR 1, сеть ограничена сверху 10 Мбит/с, задержка 100 мс. Mobile viewport: 390×844, DPR 2, 4 Мбит/с, 150 мс. Физический телефон не тестировался.
- Сеть — Chrome CDP. Холодный вход: новый контекст и очистка HTTP-кеша. Повторный: тот же контекст. Локальный сервер одинаково обслуживает зафиксированную исходную поставку и новый dist.
- Полезная сцена: первый animation frame после отправки более 10 000 треугольников WebGL. Это инструментальный признак появления модели, не независимая видеопроверка каждого пикселя. Полнота и видимость оборудования проверяются отдельно.
- Вращение: одна последовательность из 80 перемещений указателя при нажатой кнопке. Задержки обработки событий увеличивают фактическую продолжительность. FPS и p95 учитывают реальные интервалы, длительность также записывается.
- Память: измеренный максимум JS heap и выделенных vertex/index buffers. Текстуры, драйвер, полный GPU/RSS процесса в эти числа не входят; это не полная память браузера.
- Локальное ПО проверки трафика добавляет скрипт к HTML и меняет сведения о сжатии/кеше, видимые Chrome. Оно не отключалось. Сохраняются отдельно реальные браузерные результаты и проверенные серверные размеры/заголовки. Публичные timings зависят также от маршрута сети; они не используются как чистая оценка скорости сервера.
- Пробный локальный запуск с ошибочной выдачей HTML по `/favicon.ico` исключен. Основное сравнение использует исправленный сервер; favicon возвращает 204. В публичные отчеты не включаются сторонние URL с параметрами сеанса.

## Выбранные изменения и причины

1. Vite с отдельными файлами и именами по содержимому. Убирает base64 из HTML, дает ранний интерфейс и повторное использование GLB/JS/CSS из HTTP-кеша. Цена: поставку необходимо открывать через HTTP и публиковать целиком.
2. Статические тени пересчитываются только при смене состава. Свет и модель при вращении неподвижны; движется камера. Сохраняются исходные источники света, материалы, размер карты теней, контактные тени и DPR.
3. Отрисовка по запросу, явное продолжение анимации камеры. Во время перетаскивания поиск детали по всем треугольникам выключен; клик после отпускания сохраняется. Независимый code review выявил большой первый dt после простоя; шаг интерполяции ограничен 1/30 с.
4. Производная веб-сетка: Meshopt simplifier с блокировкой границ. Проверяются имена, связи узлов, исходные трансформации до квантования, материалы, байты текстур, число граней и габариты каждого компонента после декодирования. Значение error является параметром алгоритма; оно не выдается за измеренный геометрический допуск.

5. После измерения повторной загрузки модель разделена на четыре файла: котел, оборудование, кабели и деаэратор. Геометрия, индексы с учетом допустимой циклической перестановки внутри треугольника, атрибуты и габариты сравниваются с производной точно. Все четыре файла загружаются параллельно; сцена появляется после полной загрузки. Большой одиночный GLB повторно передавался в этом контексте Chrome даже с правильным Cache-Control; после разделения все файлы повторно использованы из HTTP-кеша. Конкретный внутренний лимит Chrome не установлен.

Массовый инстансинг не выбран: крепеж уже объединен внутри выбираемых компонентов. Объединять разные логические детали означало бы усложнить выбор/видимость. Дополнительные runtime LOD, динамический DPR и загрузка видимых модулей по этапам не добавлены: выбранные меры существенно увеличили плавность при сохранении качества и простого переключения состава.

## Проверка и публикация

После раздельной упаковки измеряется промежуточный вариант с неизменной геометрией. После изменений рендера/сетки — повторные сравнения и крупные планы тех же ракурсов. Проверяются реальные узлы обеих схем питания, все 27 карточек, мышь, переключатели, восстановление URL и мобильная ширина.

Публикация: локальный архив всех старых файлов с проверкой хешей; новый каталог **внутри** public_html; сверка манифеста и HTTPS staging; проверка staging в браузере; переименование старого каталога в отдельный адрес версии и перенос проверенного каталога на прежний адрес. Глобальный .htaccess и соседние разделы сверяются и не меняются. Откат возвращает старый каталог, удерживая новую версию отдельно.
