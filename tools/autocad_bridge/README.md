# Подключение AutoCAD к Codex

Версия **2026.09.08.2 от 8 сентября 2026 года**. Автор: **Codex / GPT-6 Astra**.

Модуль читает уже открытые чертежи из AutoCAD 2027 через штатный ActiveX/COM API Windows. Codex получает шесть MCP-инструментов. AutoCAD остаётся обычным приложением на компьютере пользователя. Создание нового экземпляра AutoCAD, открытие файлов и изменение рабочих чертежей через эти инструменты не предусмотрены.

Это первый этап работы с проектами котельных: получение слоёв, объектов, координат, размеров, текста и атрибутов оборудования. Построение труб, извлечение полной модели Plant 3D, согласование схем и инженерная проверка относятся к следующим этапам.

## Как пользоваться установленным подключением

1. После установки перезапустить Codex, чтобы он загрузил инструменты нового сервера `autocad`.
2. Запустить AutoCAD Plant 3D 2027 и открыть нужный DWG обычным способом.
3. Завершить текущую команду или закрыть диалог AutoCAD.
4. Попросить Codex проверить соединение, перечислить открытые чертежи и прочитать выбранный чертёж.

Пример: «Прочитай слои и единицы измерения открытого проекта котельной. Затем покажи список оборудования и укажи, какие данные ещё нужны для 3D-модели».

При повторном запуске AutoCAD модуль подключается к текущему сеансу при следующем обращении. Он не хранит старую COM-ссылку между запросами. Команды `MCPHTTPSTART`, Autodesk Assistant и Tech Preview для этого подключения не нужны. Если AutoCAD закрыт, `autocad_status` сообщает, что приложение недоступно.

## Возможности

| MCP-инструмент | Результат |
| --- | --- |
| `autocad_status` | Версия, доступность и готовность AutoCAD |
| `autocad_list_documents` | Имена, полные пути и состояние уже открытых чертежей |
| `autocad_drawing_info` | Единицы, количество объектов, слоёв и определений блоков |
| `autocad_list_layers` | Слои, видимость, цвет, блокировка |
| `autocad_list_entities` | Объекты верхнего уровня пространства модели или текущего пространства листа; выдача страницами |
| `autocad_entity_info` | Доступные стандартные свойства объекта, габариты, редактируемые атрибуты блока, координаты и bulge полилинии |

Чертёж выбирается явно по имени или `full_name` из списка открытых документов. При неоднозначности имени требуется полный путь. Выбор активной вкладки не меняется. Максимальный размер страницы — 200 объектов.

Координаты возвращаются в исходных единицах чертежа. `INSUNITS` задаёт единицы вставки и сам по себе не доказывает правильность масштаба модели. Для перевода в метры нужна сверка с известным размером. Углы ActiveX возвращаются в радианах. Координаты двумерной полилинии относятся к OCS; для восстановления в мировой системе нужны также `Normal`, `Elevation` и bulge.

Содержимое блоков и внешних ссылок не обходится рекурсивно. Геометрия тел не экспортируется в BREP. Специальные свойства Plant 3D и объекты Proxy могут быть недоступны через стандартный ActiveX. Отсутствующие свойства перечисляются явно. Текст ограничен 16 000 знаков, массивы — 12 000 значений, атрибуты блока — 200 записями, bulge — первыми 200 вершинами; усечение помечается в ответе. Чтение живого чертежа не является атомарным снимком базы.

Постоянные атрибуты блока этой версией не читаются. В ответе это явно обозначено через `constant_attributes_read=false` и `attributes_scope`. Пустой список редактируемых атрибутов не означает отсутствия постоянных атрибутов. Для больших полилиний метаданные OCS и отметка об усечении bulge сохраняются независимо от ограничения массива координат.

## Устройство и границы

```text
Codex → MCP / STDIO → Python + pywin32 → запущенный AutoCAD 2027
```

Каждый запрос создаёт собственный COM STA-контекст. Обращения сериализованы. Используется только `GetActiveObject('AutoCAD.Application.26')`; путь процесса сверяется с заданным `--autocad`. Автоматического перехода на установленный AutoCAD 2024 нет.

Сервер не открывает сетевой порт. В каталоге MCP отсутствуют выполнение Python/AutoLISP/команд AutoCAD, изменение объектов, сохранение, удаление и открытие файлов. Текст и имена из DWG рассматриваются как данные, а не инструкции. MCP-инструменты имеют `readOnlyHint=true` и `destructiveHint=false`.

Отдельная утилита `create_test_fixture.py` используется только для явной локальной проверки. Она создаёт новый тестовый чертёж с уникальным именем, сохраняет его и сравнивает состояние ранее открытых документов. В MCP-каталог и устанавливаемый сервер эта утилита не входит.

## Установка и воспроизведение проверки

Нужны Windows, уже установленный AutoCAD 2027 и Python 3.13. Проверенная среда использует `mcp==1.30.0` и `pywin32==312`. Полный набор версий закреплён в `requirements.lock.txt`.

Пример PowerShell из корня репозитория; пути нужно сверить с установкой:

```powershell
$bridgeRoot = Join-Path $env:USERPROFILE '.codex\tools\autocad-connection'
python -m venv "$bridgeRoot\.venv"
$bridgePython = "$bridgeRoot\.venv\Scripts\python.exe"
& $bridgePython -m pip install -r tools/autocad_bridge/requirements.lock.txt
& $bridgePython -m unittest discover -s tools/autocad_bridge/tests -v
& $bridgePython tools/autocad_bridge/create_test_fixture.py --autocad 'E:\AutoCAD 2027\acad.exe' --output-dir "$bridgeRoot\runtime\outputs"
```

Утилита напечатает путь JSON описания теста. Его нужно передать проверке:

```powershell
& $bridgePython tools/autocad_bridge/smoke_test.py --autocad 'E:\AutoCAD 2027\acad.exe' --server tools/autocad_bridge/server.py --fixture '<путь JSON теста>' --evidence "$bridgeRoot\runtime\source-check.json"
& $bridgePython tools/autocad_bridge/install.py --autocad 'E:\AutoCAD 2027\acad.exe' --python $bridgePython --config "$env:USERPROFILE\.codex\config.toml" --install-root $bridgeRoot
codex mcp get autocad --json
```

Установщик копирует фиксированную версию в `releases/2026.09.08.2`, сохраняет отдельную копию настроек Codex и добавляет только секцию `mcp_servers.autocad`. По умолчанию уже существующее подключение `autocad` не перезаписывается. Другие секции, включая Blender, проверяются на неизменность. Для обновления содержимого установленной версии нужна новая версия, а не замена её файлов.

При обновлении ранее установленного этим модулем подключения используется та же команда `install.py` с дополнительным флагом `--upgrade`. Установщик сверяет точный прежний блок настройки и его значения с записью прошлой установки. При любых пользовательских изменениях этого блока обновление останавливается. Старый каталог версии сохраняется; конфигурация и запись установки получают отдельные резервные копии. Замена конфигурации выполняется через временный файл и атомарное переименование.

Сервер запускается из установленного каталога, поэтому не зависит от ветки, выбранной в репозитории. Копия настроек и `installation.json` хранятся локально. Копия настроек может содержать параметры других подключений: её нельзя публиковать в GitHub.

Для отключения достаточно отключить сервер `autocad` в настройках MCP Codex. Не следует целиком восстанавливать старый `config.toml`, если после установки добавлялись другие настройки. Резервная копия предназначена для точного сравнения и восстановления только нужной секции.

## Почему используется ActiveX

На проверенном компьютере установлен официальный Autodesk AutoCAD MCP Server `26.0.460.2523`. Его подписанный модуль загружался, но `MCPHTTPSTART` оставалась неизвестной командой, включая проверку с открытым Autodesk Assistant и включённым Tech Preview. Причина недоступности команды в этой сборке не установлена. Библиотеки Autodesk и системные настройки безопасности не изменялись. Tech Preview после проверки возвращён в выключенное состояние.

Согласно [документации Autodesk MCP](https://help.autodesk.com/view/ADSKMCP/ENU/?guid=ADSKMCP_AutoCADCivil3DMcp_autodesk_autocad_civil_3d_mcp_html), поддерживаемым клиентом этого предварительного варианта является Autodesk Assistant, а AutoCAD предоставляет инструменты чтения и анализа. Поэтому для текущего подключения выбран собственный небольшой MCP-адаптер к [штатному ActiveX API AutoCAD](https://help.autodesk.com/view/ACD/2027/ENU/?caas=caas%2Fdocumentation%2FACD%2F2014%2FENU%2Ffiles%2FGUID-E6429154-36DF-4D84-8ABC-9FCA15B66158-htm.html).

Проверенная библиотека MCP: [официальный Python SDK, ветка v1.x](https://github.com/modelcontextprotocol/python-sdk/tree/v1.x). Результаты конкретной установки перечислены в [VALIDATION.md](VALIDATION.md).
