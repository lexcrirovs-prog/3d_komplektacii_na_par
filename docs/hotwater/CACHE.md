# Кэширование публичного кандидата

Версия 2026.10.19.2 · 19.10.2026 · Codex / GPT-6.

При HTTPS-проверке stage на Beget обнаружены два уровня обработки статики. GLB получают заголовки из настройки каталога assets. JavaScript и CSS обслуживаются nginx до Apache и получают срок хранилища, установленный хостингом.

| Файлы | Фактический Cache-Control | Критерий проверки |
|---|---|---|
| GLB с хешем в имени | `public, max-age=31536000, immutable` | Не меньше года, `immutable`, без `no-cache`/`no-store` |
| JS и CSS с хешем в имени | `max-age=604800` | Не меньше семи дней, без `no-cache`/`no-store` |
| HTML, version.json, DEPLOY_MANIFEST.json | `no-cache` | Повторная проверка актуальности |
| `.vite/manifest.json` | HTTP 403 | Build graph закрыт от HTTP; сверяется серверным SHA |

Изменение содержимого создаёт новый URL ресурса благодаря хешу Vite. Семидневный срок JS/CSS не мешает загрузке нового выпуска. Publisher проверяет фактически возвращаемые заголовки и SHA каждого статического файла. Почтовые PHP endpoints этой проверкой не вызываются.

Серверная конфигурация и содержимое dist для адаптации проверки не изменялись. Подробные заголовки и контрольные суммы сохраняются в `artifacts/publication-v2026.10.19.2/http-stage.json` и после публикации в `http-live.json`.
